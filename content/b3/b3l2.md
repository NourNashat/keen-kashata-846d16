## [1] المهام الأدائية

### سؤال: وضح ما هو نموذج العميل (Client) والخادم (Server).
نموذج العميل والخادم (Client/Server Model) هو نموذج اتصال تعتمد عليه كثير من تطبيقات الويب، ويتكون من طرفين رئيسيين:
1. **العميل (Client):** هو البرنامج أو الجهاز الذي يرسل طلبًا إلى خدمة أخرى للحصول على بيانات أو تنفيذ عملية، ومن أمثلته متصفح الويب وتطبيق الهاتف.
2. **الخادم (Server):** هو الجانب الذي يستقبل الطلبات من العملاء ويعالجها، ثم يعيد الاستجابات المناسبة.
وتتم عملية الاتصال من خلال إرسال العميل طلبًا عبر الشبكة إلى الخادم، ثم يقوم الخادم بمعالجة الطلب وإرسال استجابة تحتوي على البيانات المطلوبة أو نتيجة العملية.
**مثال:** عندما تفتح موقعًا إلكترونيًا وتبحث عن منتج، يكون متصفحك هو العميل الذي يرسل طلب البحث، بينما يكون الخادم هو المسؤول عن معالجة الطلب وإعادة نتائج البحث.

### سؤال: صمّم رسمًا تخطيطيًا توضح فيه كيفية التواصل بين العميل والخادم.
**العميل (Client)**
متصفح الويب أو تطبيق الهاتف
⬇ إرسال الطلب (Request)
**الخادم (Server)**
استقبال الطلب ومعالجته
⬇ إرسال الاستجابة (Response)
**العميل (Client)**
استقبال البيانات وعرض النتيجة
يتم تبادل الطلبات والاستجابات عبر الشبكة باستخدام بروتوكولات الاتصال مثل HTTP وHTTPS.

### اختيار: العميل في تطبيقات الويب هو:
- [ ] الخادم الذي يعالج الطلبات.
- [x] البرنامج أو الجهاز الذي يرسل الطلبات.
- [ ] قاعدة البيانات.
- [ ] بروتوكول الاتصال.
> العميل هو الطرف الذي يبدأ الاتصال بإرسال طلب إلى الخادم، مثل متصفح الويب أو تطبيق الهاتف.

### اختيار: عند إرسال بيانات تسجيل الدخول يُفضل استخدام:
- [ ] GET
- [x] POST
- [ ] 200
- [ ] 404
> يُستخدم POST عادةً لإرسال البيانات إلى الخادم، مثل بيانات تسجيل الدخول ومحتويات النماذج، بينما يُستخدم GET عادةً لطلب البيانات واسترجاعها.

## [1] أداءات منزلية

### سؤال: لماذا يُعتبر بروتوكول HTTPS أكثر أمانًا من HTTP؟ أعط مثالًا.
يُعتبر بروتوكول HTTPS أكثر أمانًا من HTTP لأنه يستخدم بروتوكول TLS لتأمين الاتصال بين العميل والخادم، مما يساعد على:
1. **حماية سرية البيانات:** عن طريق تشفير البيانات أثناء انتقالها عبر الشبكة، مما يصعب على المتجسس قراءتها.
2. **حماية سلامة البيانات:** يساعد على اكتشاف التلاعب بالبيانات أثناء نقلها.
3. **مصادقة الخادم:** يساعد على التأكد من هوية الخادم الذي يتصل به المستخدم.
**مثال:** عند تسجيل الدخول إلى موقع إلكتروني وإدخال اسم المستخدم وكلمة المرور، يساعد HTTPS على حماية هذه البيانات من التجسس أثناء انتقالها من المتصفح إلى الخادم.

### سؤال: وضّح الفرق بين طلب GET وطلب POST مع مثال لكل منهما.
|وجه المقارنة|GET|POST
|الوظيفة|طلب مورد أو بيانات من الخادم|إرسال بيانات ليعالجها الخادم
|الاستخدام|استرجاع صفحة ويب أو نتائج البحث|إرسال بيانات تسجيل الدخول أو محتويات نموذج
|مثال|البحث عن منتج وعرض النتائج|إرسال بيانات تسجيل مستخدم جديد
**مثال على GET:** عندما يكتب المستخدم اسم منتج في مربع البحث ويطلب عرض المنتجات المطابقة، يُستخدم GET عادةً لاسترجاع نتائج البحث.
**مثال على POST:** عندما يملأ المستخدم نموذج تسجيل الدخول ويرسل اسم المستخدم وكلمة المرور إلى الخادم، يُستخدم POST عادةً لإرسال هذه البيانات.
**ملحوظة مهمة:** استخدام POST لا يعني أن البيانات مشفرة تلقائيًا؛ فتأمين البيانات أثناء النقل يتطلب استخدام HTTPS.

### اختيار: رمز الحالة 200 يعني:
- [ ] خطأ داخلي في الخادم.
- [x] نجاح الطلب.
- [ ] المورد غير موجود.
- [ ] طلب غير مصرح به.
> رمز الحالة HTTP 200 يشير إلى أن الخادم نجح في معالجة الطلب.

### اختيار: رمز الحالة 404 يشير إلى:
- [ ] نجاح الطلب.
- [ ] خطأ داخلي في الخادم.
- [x] المورد غير موجود.
- [ ] الاتصال آمن.
> يظهر الرمز 404 عندما لا يتم العثور على المورد المطلوب على الخادم بالعنوان المحدد.

## [2] المهام الأدائية

### سؤال: فسّر معنى رمز الحالة 200 في HTTP.
رمز الحالة HTTP 200 يعني نجاح الطلب (OK)، أي أن الخادم استقبل الطلب وتمكن من معالجته بنجاح، وأرسل استجابة ناجحة إلى العميل.
**مثال:** عندما يطلب المستخدم صفحة ويب موجودة ويستطيع الخادم إرجاعها بنجاح، يمكن أن تكون الاستجابة مصحوبة برمز الحالة 200.

### سؤال: ماذا يعني رمز الحالة 404؟ ومتى يظهر؟
رمز الحالة HTTP 404 يعني أن المورد المطلوب غير موجود (Not Found)، ويظهر عندما يطلب العميل صفحة أو ملفًا أو موردًا غير موجود على الخادم بالعنوان المحدد.
**مثال:** عندما يحاول المستخدم فتح رابط لصفحة تم حذفها أو كتابة عنوان صفحة غير موجودة، قد يعيد الخادم رمز الحالة 404.

### اختيار: الفرق الأساسي بين HTTP و HTTPS هو:
- [x] HTTPS يستخدم تشفير TLS.
- [ ] HTTP أسرع دائمًا.
- [ ] HTTPS لا يدعم POST.
- [ ] HTTP يستخدم JSON.
> يستخدم HTTPS بروتوكول HTTP عبر اتصال آمن بواسطة TLS، مما يساعد على حماية سرية البيانات وسلامتها ومصادقة الخادم.

### اختيار: صيغة JSON تُستخدم في:
- [ ] تصميم واجهة المستخدم.
- [x] تبادل البيانات المهيكلة.
- [ ] تشفير الاتصال.
- [ ] تحديد رمز الحالة.
> JSON هي صيغة نصية شائعة لتمثيل وتبادل البيانات المهيكلة باستخدام الكائنات والمصفوفات والقيم البسيطة.

## [2] أداءات منزلية

### سؤال: ما دور رمز الحالة 500 في الاتصال بين العميل والخادم؟
رمز الحالة HTTP 500 يعني حدوث خطأ داخلي في الخادم (Internal Server Error)، وهو يشير إلى أن الخادم واجه مشكلة داخلية منعته من إكمال معالجة الطلب بنجاح.
ويتم إرساله إلى العميل لإعلامه بأن المشكلة حدثت من جانب الخادم، لكنه لا يحدد وحده السبب التفصيلي للخطأ.
**مثال:** عندما يرسل المستخدم طلبًا لفتح صفحة، ولكن يحدث خلل برمجي أو مشكلة داخل الخادم تمنعه من تنفيذ الطلب، فقد يعيد الخادم رمز الحالة 500.

### سؤال: ما هو الـ API؟ وكيف يساعد في تطوير تطبيقات الويب؟
واجهة برمجة التطبيقات (API - Application Programming Interface) هي مجموعة من القواعد الواضحة التي تسمح لبرنامج بطلب بيانات أو وظائف من برنامج آخر أو خدمة أخرى.
وتساعد API في تطوير تطبيقات الويب من خلال:
1. السماح للواجهة الأمامية بالتواصل مع الخدمات الموجودة في الواجهة الخلفية.
2. تسهيل تبادل البيانات بين التطبيقات والأنظمة المختلفة.
3. إعادة البيانات المطلوبة إلى التطبيق باستخدام صيغ منظمة مثل JSON.
4. إعادة استخدام الوظائف والخدمات دون الحاجة إلى كتابة جميع العمليات من البداية.
**مثال:** عندما يستخدم تطبيق الطقس خدمة خارجية للحصول على حالة الطقس في مدينة معينة، يمكنه إرسال طلب عبر API إلى خدمة الطقس، ثم يستقبل البيانات ويعرضها للمستخدم.

### اختيار: الـ API هو:
- [ ] قاعدة بيانات.
- [x] مجموعة قواعد للتواصل بين البرامج.
- [ ] بروتوكول أمني.
- [ ] صيغة بيانات.
> API تحدد طريقة التواصل وطلب البيانات أو الوظائف بين البرامج والخدمات المختلفة.

### اختيار: عند عرض نتائج البحث من الخادم يُستخدم عادةً:
- [ ] POST
- [x] GET
- [ ] 500
- [ ] HTTPS
> يُستخدم GET عادةً لطلب واسترجاع البيانات من الخادم، مثل نتائج البحث وصفحات الويب.

## [3] النموذج (A)

### سؤال: اشرح نموذج العميل والخادم.
نموذج العميل والخادم هو نموذج اتصال تعتمد عليه تطبيقات الويب، ويتكون من طرفين:
- **العميل (Client):** هو البرنامج أو الجهاز الذي يرسل الطلبات للحصول على البيانات أو تنفيذ عملية، مثل متصفح الويب.
- **الخادم (Server):** هو الجانب الذي يستقبل الطلبات ويعالجها ثم يعيد الاستجابات المناسبة.
وتتم العملية من خلال إرسال العميل طلبًا إلى الخادم عبر الشبكة، ثم يعالج الخادم الطلب ويرسل الاستجابة إلى العميل.

### سؤال: لماذا يجب استخدام HTTPS في صفحة تسجيل الدخول؟
يجب استخدام HTTPS في صفحة تسجيل الدخول لأنه يوفر اتصالًا آمنًا بين العميل والخادم باستخدام بروتوكول TLS، مما يساعد على:
1. تشفير بيانات تسجيل الدخول أثناء انتقالها عبر الشبكة.
2. حماية سرية اسم المستخدم وكلمة المرور من التجسس.
3. حماية سلامة البيانات من التعديل أثناء النقل.
4. المساعدة في التأكد من هوية الخادم الذي يتصل به المستخدم.

### سؤال: ما دور الـ API في تطبيقات الويب؟
تتمثل وظيفة API في توفير مجموعة من القواعد التي تسمح للبرامج والتطبيقات بالتواصل وتبادل البيانات والوظائف فيما بينها.
وتُستخدم في تطبيقات الويب لتمكين الواجهة الأمامية من إرسال طلبات إلى الخدمات الخلفية والحصول على البيانات المطلوبة، والتي قد تُعاد بصيغة JSON.

### سؤال: فسّر رمز الحالة 200.
رمز الحالة HTTP 200 يعني نجاح الطلب (OK)، أي أن الخادم تمكن من استقبال الطلب ومعالجته بنجاح وإرسال الاستجابة المطلوبة إلى العميل.

### اختيار: أي مما يأتي يمثل دور العميل (Client) في تطبيق ويب؟
- [ ] معالجة الطلبات على الخادم.
- [x] إرسال الطلبات للحصول على البيانات.
- [ ] تخزين البيانات في قاعدة البيانات.
- [ ] تحديد الجمهور المستهدف للمنشورات.
> العميل هو البرنامج أو الجهاز الذي يرسل الطلبات إلى الخادم للحصول على البيانات أو تنفيذ العمليات.

### اختيار: أي مما يأتي يُستخدم عادةً لطلب مورد أو بيانات من الخادم؟
- [ ] POST
- [x] GET
- [ ] API
- [ ] JSON
> GET هي طريقة طلب HTTP تُستخدم عادةً لاسترجاع مورد أو بيانات من الخادم.

### اختيار: أي مما يأتي يُعتبر صيغة شائعة لتبادل البيانات بين التطبيقات؟
- [ ] HTML
- [x] JSON
- [ ] CSS
- [ ] SQL
> JSON صيغة نصية شائعة لتمثيل البيانات المهيكلة وتبادلها بين التطبيقات.

### اختيار: رمز الحالة 404 يعني:
- [ ] نجاح الطلب.
- [ ] خطأ داخلي في الخادم.
- [x] المورد المطلوب غير موجود.
- [ ] الطلب لم يُرسل.
> يشير الرمز 404 إلى عدم العثور على المورد المطلوب على الخادم بالعنوان المحدد.

## [3] النموذج (B)

### سؤال: اشرح لماذا يُعتبر نموذج الطلب والاستجابة أساسيًا في تطبيقات الويب، مع ذكر مثال عملي.
يُعتبر نموذج الطلب والاستجابة أساسيًا في تطبيقات الويب لأنه ينظم طريقة التواصل بين العميل والخادم، حيث يقوم العميل بإرسال طلب للحصول على بيانات أو تنفيذ عملية، ثم يستقبل الخادم الطلب ويعالجه ويرسل استجابة تحتوي على النتيجة المطلوبة.
وتكمن أهميته في أنه يسمح للتطبيقات بطلب البيانات ومعالجتها وإرجاع النتائج بطريقة منظمة عبر الشبكة.
**مثال على العميل:** متصفح Google Chrome، حيث يرسل طلبًا إلى خادم الموقع عند فتح صفحة ويب، ثم يستقبل استجابة الخادم ويعرض الصفحة للمستخدم.

### سؤال: ميّز بين استخدام طريقة GET وطريقة POST، وحدد مواقف مناسبة لكل منهما.
- **GET:** تُستخدم عادةً لطلب مورد أو استرجاع بيانات من الخادم، مثل عرض صفحة ويب أو الحصول على نتائج البحث.
- **POST:** تُستخدم عادةً لإرسال بيانات إلى الخادم ليتم معالجتها، مثل إرسال بيانات تسجيل الدخول أو تسجيل مستخدم جديد أو إرسال محتويات نموذج.
**المواقف المناسبة:**
- نستخدم GET عندما نريد استرجاع بيانات أو عرض نتائج بحث.
- نستخدم POST عندما نريد إرسال بيانات إلى الخادم لتنفيذ عملية أو معالجتها.

### سؤال: اشرح أهمية بروتوكول HTTPS في حماية البيانات أثناء النقل عبر الشبكة.
يُعد بروتوكول HTTPS مهمًا لحماية البيانات أثناء انتقالها بين العميل والخادم؛ لأنه يستخدم بروتوكول TLS لتأمين الاتصال، ويساعد على:
1. الحفاظ على سرية البيانات عن طريق تشفيرها أثناء النقل.
2. حماية سلامة البيانات والمساعدة على اكتشاف التعديل عليها.
3. مصادقة الخادم والتحقق من هويته.
**مثال:** عند استخدام صفحة دفع إلكتروني، يساعد HTTPS على حماية بيانات المستخدم أثناء انتقالها من المتصفح إلى الخادم.

### سؤال: صمّم طريقة اتصال مناسبة لمهمة في تطبيق ويب (مثل تسجيل مستخدم جديد).
يمكن تصميم طريقة اتصال مناسبة لتسجيل مستخدم جديد وفقًا للخطوات التالية:
1. يعرض العميل (متصفح الويب) نموذج تسجيل يحتوي على الاسم والبريد الإلكتروني وكلمة المرور.
2. يُدخل المستخدم بياناته ويضغط على زر التسجيل.
3. ترسل الواجهة الأمامية البيانات إلى الخادم باستخدام طلب HTTP POST عبر اتصال HTTPS.
4. يستقبل الخادم البيانات ويتحقق من صحتها، مثل التأكد من صحة البريد الإلكتروني وعدم وجود حساب مسجل به بالفعل.
5. يتواصل الخادم مع قاعدة البيانات لحفظ بيانات المستخدم الجديد إذا كانت صحيحة.
6. تعيد الخدمة استجابة إلى العميل توضح نجاح التسجيل أو سبب فشله.
7. يعرض المتصفح رسالة مناسبة للمستخدم.
**سبب اختيار POST:** لأنه يُستخدم عادةً لإرسال بيانات النماذج إلى الخادم من أجل معالجتها.
**سبب اختيار HTTPS:** لحماية البيانات أثناء انتقالها بين العميل والخادم.

### اختيار: أي من رموز الحالة التالية يُشير إلى نجاح الطلب؟
- [x] 200
- [ ] 404
- [ ] 500
- [ ] 302
> يشير رمز الحالة 200 إلى نجاح معالجة الطلب من جانب الخادم.

### اختيار: أي مما يأتي يُستخدم عادةً لإرسال بيانات النموذج إلى الخادم؟
- [ ] GET
- [x] POST
- [ ] API
- [ ] JSON
> يُستخدم POST عادةً لإرسال البيانات إلى الخادم ليتم معالجتها، مثل بيانات النماذج وتسجيل المستخدمين.

### اختيار: ما الواجهة التي تسمح للتطبيقات بالتواصل وتبادل البيانات؟
- [ ] HTML
- [x] API
- [ ] CSS
- [ ] SQL
> API هي واجهة برمجة التطبيقات التي توفر قواعد محددة تسمح للبرامج والخدمات بالتواصل وتبادل البيانات والوظائف.

### اختيار: اختر ما يُعتبر مثالًا على صيغة بيانات تُستخدم في تبادل المعلومات بين التطبيقات.
- [ ] XML
- [x] JSON
- [ ] PHP
- [ ] Java
> JSON صيغة بيانات نصية شائعة تُستخدم لتمثيل البيانات المهيكلة وتبادلها بين التطبيقات المختلفة (وهي الإجابة المعتمدة في التقييم، أما PHP وJava فهما لغتا برمجة).

## [3] النموذج (C)

### سؤال: اشرح كيف يتعامل الخادم مع الطلبات الواردة من العميل، وما الذي يحدث إذا كان الطلب غير صحيح أو غير موجود.
عندما يرسل العميل طلبًا إلى الخادم، يقوم الخادم باستقبال الطلب وتحليله ومعالجته وفقًا لنوع العملية المطلوبة وقواعد التطبيق، ثم يرسل استجابة إلى العميل تتضمن نتيجة المعالجة ورمز حالة HTTP يوضح نتيجة الطلب.
وتختلف الاستجابة حسب نتيجة المعالجة:
- إذا تمت معالجة الطلب بنجاح: يعيد الخادم رمز الحالة 200.
- إذا كان المورد المطلوب غير موجود: يعيد الخادم رمز الحالة 404.
- إذا حدث خطأ داخلي في الخادم منعه من إكمال الطلب: يعيد الخادم رمز الحالة 500.
وبذلك تساعد رموز الحالة العميل على معرفة نتيجة الطلب، سواء تمت معالجته بنجاح أو حدثت مشكلة أثناء التنفيذ.

### سؤال: فسّر دور واجهات برمجة التطبيقات (API) في ربط تطبيقات مختلفة، مع مثال عملي.
تعمل واجهات برمجة التطبيقات (API) كوسيلة منظمة للتواصل بين البرامج والتطبيقات المختلفة، حيث توفر مجموعة من القواعد التي تسمح لتطبيق بطلب بيانات أو وظائف من تطبيق أو خدمة أخرى.
وتساعد API على ربط الأنظمة المختلفة وتبادل البيانات بينها دون الحاجة إلى معرفة التفاصيل الداخلية لطريقة عمل كل نظام.
**مثال:** تطبيق الطقس على الهاتف يمكنه استخدام API للتواصل مع خدمة طقس خارجية، وإرسال طلب للحصول على حالة الطقس في مدينة معينة، ثم تستجيب الخدمة بالبيانات المطلوبة بصيغة JSON ليعرضها التطبيق للمستخدم.

### سؤال: اشرح كيف تُستخدم صيغة JSON في تبادل البيانات، ولماذا تُعتبر مناسبة لتطبيقات الويب.
تُستخدم صيغة JSON (JavaScript Object Notation) لتمثيل وتبادل البيانات المهيكلة بين التطبيقات والأنظمة المختلفة، وذلك باستخدام الكائنات والمصفوفات والقيم البسيطة.
وتُعتبر مناسبة لتطبيقات الويب للأسباب التالية:
1. صيغة نصية سهلة القراءة والفهم.
2. تساعد على تنظيم البيانات في صورة مهيكلة.
3. تدعمها لغات البرمجة والأدوات المختلفة.
4. تسهل تبادل البيانات بين الواجهة الأمامية والخدمات الخلفية.
5. يمكن استخدامها لنقل بيانات متعددة، مثل أسماء المستخدمين والمنتجات والأسعار ونتائج البحث.
**مثال:** يمكن أن يعيد الخادم بيانات منتج إلى الواجهة الأمامية بصيغة JSON تحتوي على اسم المنتج وسعره، ثم تستخدم الواجهة الأمامية هذه البيانات لعرض المنتج للمستخدم.

### سؤال: اقترح سيناريو لتطبيق ويب يحتاج إلى استخدام طريقة POST، ووضح سبب اختيارك لها.
**السيناريو:** تطبيق ويب يسمح للمستخدمين بإنشاء حساب جديد.
يقوم المستخدم بفتح صفحة التسجيل وإدخال بياناته، مثل الاسم والبريد الإلكتروني وكلمة المرور، ثم يضغط على زر إنشاء الحساب.
ترسل الواجهة الأمامية البيانات إلى الخادم باستخدام طريقة POST، ويستقبل الخادم البيانات ويتحقق من صحتها، ثم يتواصل مع قاعدة البيانات لحفظ بيانات المستخدم الجديد، وبعد ذلك يعيد استجابة توضح نجاح عملية التسجيل أو فشلها.
**سبب اختيار POST:** لأنها تُستخدم عادةً لإرسال البيانات إلى الخادم من أجل معالجتها، وهو ما يناسب عملية تسجيل مستخدم جديد.
ويُفضل استخدام HTTPS مع POST لحماية البيانات أثناء انتقالها من العميل إلى الخادم.

### اختيار: أي من رموز الحالة التالية يُشير إلى خطأ داخلي في الخادم؟
- [ ] 200
- [ ] 404
- [x] 500
- [ ] 302
> يشير رمز الحالة 500 إلى حدوث خطأ داخلي في الخادم منعه من إكمال معالجة الطلب.

### اختيار: أحد هذه التقنيات يُستخدم عادةً لطلب صفحة ويب أو نتائج بحث:
- [ ] POST
- [x] GET
- [ ] API
- [ ] JSON
> تُستخدم طريقة GET عادةً لطلب الموارد والبيانات من الخادم، مثل صفحات الويب ونتائج البحث.

### اختيار: ما الصيغة النصية التي تُستخدم لتمثيل البيانات المهيكلة باستخدام كائنات ومصفوفات؟
- [ ] HTML
- [x] JSON
- [ ] CSS
- [ ] SQL
> JSON صيغة نصية تمثل البيانات المهيكلة باستخدام الكائنات والمصفوفات والقيم البسيطة.

### اختيار: أي مما يأتي يُستخدم لتأمين الاتصال بين العميل والخادم ومنع التجسس؟
- [ ] HTTP
- [x] HTTPS
- [ ] API
- [ ] JSON
> يستخدم HTTPS بروتوكول TLS لتأمين الاتصال، مما يساعد على حماية البيانات من التجسس والتعديل أثناء انتقالها.
